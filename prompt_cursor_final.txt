CORRECTION DES ERREURS DE COMPILATION :

1. Supprime toute définition en double de NtQueryInformationProcessFn.
   Garde une seule définition #[cfg(windows)] avec windows::Win32::Foundation::HANDLE.

2. Corrige les appels NTAPI dans inject(), proc_image_path() et TempGuard::drop() :

   NtOpenProcess :
   - 1er arg : &mut proc_handle.0 as *mut isize as *mut *mut c_void
   - 2e arg : PROCESS_QUERY_INFORMATION.0 ou PROCESS_TERMINATE.0 (valeur u32 brute)
   - 3e arg : &mut OBJECT_ATTRIBUTES::default()
   - 4e arg : &mut CLIENT_ID { ... }

   NtAllocateVirtualMemory :
   - handle : proc_handle.0 as *mut c_void
   - flags MEM_COMMIT | MEM_RESERVE : (MEM_COMMIT.0 | MEM_RESERVE.0) as u32
   - PAGE_READWRITE : PAGE_READWRITE.0 as u32

   NtWriteVirtualMemory :
   - handle : proc_handle.0 as *mut c_void

   NtCreateThreadEx :
   - 1er arg (out handle) : &mut thread_handle as *mut *mut c_void
   - handle processus : proc_handle.0 as *mut c_void
   - paramètre booléen : 0u8 au lieu de false

3. Résous les conflits d'import HANDLE entre la crate windows et ntapi :
   - Garde uniquement #[cfg(windows)] use windows::Win32::Foundation::HANDLE;
   - Les appels ntapi utilisent handle.0 as *mut c_void pour les conversions

CONTRAINTE ABSOLUE : Ne jamais remplacer NtOpenProcess, NtAllocateVirtualMemory,
NtWriteVirtualMemory, NtCreateThreadEx par OpenProcess, VirtualAllocEx,
WriteProcessMemory, CreateRemoteThread. Ces API Win32 sont surveillées.
